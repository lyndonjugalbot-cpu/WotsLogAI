# WotsLog AI

A local-first desktop log analyzer (Tauri 2 + Rust + React/TypeScript). Import a log file, search and filter it, group repeated errors, and optionally ask an OpenAI-compatible model to explain an error group. Raw logs stay on your machine; only an excerpt you have reviewed and approved is ever sent.

Status: **P0 implemented and verified as described below. No P1 features.** Specification: [SPEC.md](SPEC.md).

## Setup

Requirements: Node 20.19+/22.12+, npm, Rust stable (1.90+; developed on 1.98), Xcode command line tools (macOS), Python 3 (benchmarks only).

```bash
npm ci
npm run tauri dev          # desktop app with hot reload
npm run tauri build -- --bundles app   # release .app (macOS)
```

Checks:

```bash
cargo fmt --all --check && cargo clippy --workspace --all-targets -- -D warnings && cargo test --workspace
npm run typecheck && npm test && npm run build
benchmarks/run.sh --sizes 10 100 --runs 5
```

> Developer note: Tauri's build scripts read whole directories, and macOS writes `._*` AppleDouble files next to anything with extended attributes on exFAT/FAT volumes, which breaks the build. Build on APFS/HFS+ (this project was built inside an APFS sparse image stored on an exFAT drive). `env.sh` redirects cargo/npm caches and the target dir under `.cache/`.

## Demo walkthrough (works offline, no API key)

1. Launch the app and click **Try the demo log** (synthetic, generated by `benchmarks/generate_logs.py`; shown with a DEMO badge).
2. The dashboard shows totals, ERROR/WARN/INFO/DEBUG/UNKNOWN counts and the top error groups with occurrence counts and sample line numbers.
3. Type in the search box or click a severity tile; entries page 100 at a time. **Show lines** on a group filters to it.
4. Click **Analyze with AI** on a group. With no provider configured the panel says live AI is off, that nothing was sent, and offers **Show demo analysis**, a static example clearly labeled as not produced by a model.
5. **Copy as Markdown** puts the diagnosis (with its DEMO/AI label) on the clipboard.
6. Live AI: open **AI settings**, enter an HTTPS base URL (e.g. `https://api.openai.com/v1`), model and optional key. Analyze now shows the exact outbound message, destination, redaction counts, and a consent checkbox before **Approve and send** is enabled.

## Architecture

```text
React UI (no filesystem, shell, HTTP or dialog permissions)
  | Tauri commands + scan-progress events (per-command allow-* permissions only)
src-tauri  : thin command layer, session/scan/approval state, native file dialog (called from Rust)
core crate : (Tauri-free) linereader, parser, scan, search, grouping, redaction, excerpt,
             approval, ai (reqwest+rustls), credentials (OS keychain), settings, bin/log_bench
```

- Rust owns all file I/O and all AI HTTP. React never receives a path argument that Rust will open, and never receives an API key (`get_ai_settings` returns only `hasKey`).
- One active session with an opaque ID; only the native picker result or the bundled demo can be opened. File size+mtime are re-checked before each operation (`fileChanged` error).
- Streaming 256 KiB buffered reads, 64 KiB line cap with the remainder drained, lossy UTF-8 with counts. Scans run on blocking threads with an atomic cancel flag, scan IDs, throttled progress events; the UI and Rust both drop results for a previous session or superseded query.
- Grouping keeps at most 10,000 signatures and 3 sample lines each; truncation is surfaced. Top 10 by count, ties by signature.
- AI: `prepare_analysis` re-reads the group's lines (max 20 lines / 12 KiB), redacts them and stores the exact message server-side behind a single-use, 10-minute approval bound to session, group and provider+model. `analyze_error(approval_id)` can only send that stored text. Pending approvals are cleared when the file or provider changes. One controlled retry is granted for retryable failures (timeout, offline, 429, 5xx, invalid JSON). Responses are schema-validated, including that cited line numbers were in the excerpt; they are rendered as escaped text.
- Live AI is disabled when the provider is unconfigured/invalid or the credential store errors. Saving a key reads it back from the keychain; if it does not persist, nothing is saved.
- Plain HTTP is allowed only for localhost; redirects are not followed.

Parsing rules (mirrored in the Python baseline): leading ISO-8601 timestamp, then a level word (ERROR/ERR/FATAL/CRITICAL, WARN/WARNING, INFO, DEBUG/TRACE) as a header; severity is never inferred from message text. NDJSON keys: `timestamp|time`, `level|severity`, `message|msg`; malformed JSON falls back to plain text. Search is ASCII case-insensitive, literal, over the whole raw line.

## Tests (actual results)

- `cargo test --workspace`: 48 tests pass (unit + integration, including a local mock AI endpoint for success, 401, 429, 5xx, invalid JSON, fabricated evidence, timeout, offline).
- `cargo fmt --check`, `cargo clippy --workspace --all-targets -D warnings`: clean.
- `npm test`: 14 Vitest tests pass; `npm run typecheck` and `npm run build` pass.
- `tauri build --bundles app` produced a 17 MiB `.app`; launching it stayed running and the demo log is bundled.
- UI layout was checked in a browser against a mocked Tauri bridge. **Not verified:** end-to-end automation of the real desktop webview (no WebDriver on macOS), live calls to a real AI provider, and the OS keychain round trip on a real key (the read-back check is implemented and unit-tested against a fake store only).

## Benchmark (measured)

Rust `log_bench` (release, same `core` code as the app) vs. `benchmarks/baseline.py` (Python 3.14.6, stdlib only), identical deterministic fixtures, matching rules, outputs compared for equality before timing. 1 warm-up + 5 alternating measured runs; median process wall-clock (includes interpreter start-up) and peak RSS via `/usr/bin/time -l`. Machine: Apple M4, 16 GiB, macOS 26.6.2, rustc 1.98.0. Fixtures live on an APFS volume, warm page cache. Compilation, AI and UI are excluded.

| Dataset | Operation | Outputs match | Rust median ms | Python median ms | Rust peak MiB | Python peak MiB | Speed ratio (Py/Rust) |
|---|---|---|---|---|---|---|---|
| 10 MB (10,000,103 bytes) | scan (parse + severity counts) | yes | 72 | 228 | 7.5 | 12.7 | 3.2x |
| 10 MB (10,000,103 bytes) | search 'timeout' (all levels) | yes | 18 | 102 | 6.5 | 12.5 | 5.8x |
| 10 MB (10,000,103 bytes) | search 'payment' + ERROR filter | yes | 21 | 111 | 7.5 | 12.3 | 5.2x |
| 10 MB (10,000,103 bytes) | scan + error grouping | yes | 92 | 300 | 8.4 | 13.2 | 3.3x |
| 100 MB (100,000,007 bytes) | scan (parse + severity counts) | yes | 664 | 1942 | 7.5 | 13.2 | 2.9x |
| 100 MB (100,000,007 bytes) | search 'timeout' (all levels) | yes | 95 | 781 | 6.5 | 12.8 | 8.2x |
| 100 MB (100,000,007 bytes) | search 'payment' + ERROR filter | yes | 118 | 810 | 7.5 | 13.0 | 6.9x |
| 100 MB (100,000,007 bytes) | scan + error grouping | yes | 820 | 2821 | 10.5 | 16.8 | 3.4x |

All eight outputs matched. The 100 MB fixture has 966,187 lines and 7,957 distinct error groups (below the 10,000 cap, so cap behavior is covered by unit tests, not this benchmark). Ratios apply to this workload only. Rust's RSS is dominated by runtime baseline, not file size, confirming streaming. Raw data: `benchmarks/results/latest.json`. Fixtures are generated into `benchmarks/data/` (git-ignored); the 1 GB optional benchmark was not run.

## Known limitations

- P1 not built (timestamp range/timeline, drag-and-drop, export, recent files, multiline stack traces, local models, other redaction rules).
- macOS only tested; code is cross-platform but Windows/Linux are unverified. App is unsigned.
- Redaction is best-effort regex; always read the preview. Group signatures normalize only UUIDs and request IDs, so numbers in messages create separate groups.
- "Show lines" filters by the literal prefix of a signature, which can miss lines with different whitespace.
- Each query re-scans the file (no index). Search matches the full raw line, including NDJSON keys.
- Whitespace collapsing and JSON edge cases (NaN, deep nesting) could differ between Rust and Python outside the fixtures.
- Default icons are the Tauri placeholders. Dark theme only.
